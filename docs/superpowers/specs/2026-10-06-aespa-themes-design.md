# aespa Themes for VS Code: design

Date: 2026-10-06

## Goal

A single VS Code extension that ships one color theme per aespa era, so the editor can be re-skinned the way the Winter fansite re-skins itself per era. The visual seed for each era is the fansite spec's era token table (`~/work/winter-fansite/docs/superpowers/specs/2026-10-05-winter-fansite-design.md`, lines 84-95).

## Scope

In:

- 12 themes, one per era that has hex values in the fansite spec: Black Mamba, Next Level, Savage, Girls, MY WORLD, Drama, Armageddon, Whiplash, Dirty Work, Rich Man, LEMONADE, KISS N TELL.
- Dark base (`vs-dark`) for nine eras. Light base (`vs`) for the three candy eras whose dominant color is light: Rich Man, LEMONADE, KISS N TELL.
- Full workbench coverage (about 250 keys, including the 2026 Modern UI keys), TextMate token rules for JS/TS, Python, CSS, HTML, JSON, Markdown, diff and regex, and semantic token colors.
- Generated theme JSON from a typed per-era palette, with tests.
- Packaged as a VSIX under publisher `AustinSenna`, same layout as `digimon-vscode`.

Out (v1):

- Eras with no color data in the fansite (Forever, Dreams Come True, Better Things, Attitude, Parallel Line, aeXIS Line, WDA, Winter solo).
- Member themes.
- High-contrast variants.
- A runtime extension (no `main`, no settings, no commands).

## Architecture

```
aespa-themes/
  package.json              contributes.themes is generated by build
  src/
    color.ts                hex parsing, alpha, mix, WCAG contrast
    palette.ts              EraPalette type and role names
    eras/<slug>.ts          one hand-tuned palette per era
    eras/index.ts           ordered list of eras
    workbench.ts            roles -> workbench color keys
    tokens.ts               roles -> tokenColors rules
    semantic.ts             roles -> semanticTokenColors
    theme.ts                compileTheme(era) -> theme JSON object
    build.ts                writes themes/*.json and syncs package.json
    schema/workbench-keys.json   every valid workbench color key
  scripts/update-keys.ts    refreshes workbench-keys.json from vscode-docs
  test/                     vitest
  themes/                   generated, committed
```

### Palette roles

Each era file exports an `EraPalette`:

- `seed`: the fansite's `a`, `b`, `glow` values, kept verbatim for traceability.
- `bg`: `base` (editor), `mantle` (side bar, panels), `crust` (title bar, status bar, deepest chrome).
- `surface`: `s0`, `s1`, `s2`: hover, selection, overlays, in increasing prominence.
- `border`.
- `fg`: `text`, `subtext`, `muted`.
- `accent`: the era's signature color. Cursor, active borders, badges, buttons, focus.
- `accent2`: secondary accent. Remote status item, secondary buttons, progress.
- `syntax`: `keyword`, `storage`, `string`, `number`, `function`, `type`, `variable`, `property`, `comment`, `operator`, `tag`, `attribute`, `regexp`, `escape`.
- `status`: `success`, `warning`, `error`, `info`.
- `ansi`: optional overrides; defaults derive from `status`, `syntax` and `fg`.
- `style`: `italicComments`, `boldKeywords`, `underlineTypes`. Whiplash uses the last two because it has no hue to spend.

The three seed colors anchor each file; the rest is hand-picked per era so Savage reads acid-on-purple and Drama reads red-and-gold.

### Generation

`compileTheme` takes an `EraPalette` and returns `{ name, type, semanticHighlighting: true, colors, tokenColors, semanticTokenColors }`. `build.ts` writes one `themes/<slug>-color-theme.json` per era and rewrites `contributes.themes` in `package.json` from the era index, so the two cannot drift. `vscode:prepublish` runs the build so a VSIX is always fresh.

### Testing

- Every emitted workbench key is in `workbench-keys.json`.
- Every color value parses as `#RGB`, `#RGBA`, `#RRGGBB` or `#RRGGBBAA`.
- Every `syntax` role, `fg` step except `muted`, and every ANSI color clears 4.5:1 contrast against `bg.base` (the terminal rewrites colors below 4.5:1 by default, so this is the floor at which users see the real palette). `fg.muted` and `syntax.comment` clear 3:1.
- Every era in the index has a matching `contributes.themes` entry and a generated file.
- `semanticTokenColors` selectors match VS Code's selector grammar.

### Verification

`vsce package` produces a VSIX, `code --install-extension` installs it, and a screenshot of a few themes confirms the look.

## Revision 2 (same day): derived palettes, icon themes, runtime

After the first build, several hand-picked palettes had syntax colors spanning OKLCH lightness 0.65 to 0.92 and chroma 0.06 to 0.24 within one theme. Research into well-regarded themes (Catppuccin, Rosé Pine, Tokyo Night, Nord, GitHub) gave numeric bands, and the palettes are now derived:

- `src/derive.ts` takes an `EraSpec` (background hue and optional lightness, mood, two UI accents, a hue per syntax role) and emits an `EraPalette`. Dark: backgrounds L 0.21-0.23 tinted toward the era hue, surfaces +0.07 per step, text L 0.88, subtext 0.78, comments 0.69, accents L 0.80-0.82 with chroma 0.09-0.14 by mood, errors +0.02 chroma. Light: background L 0.965, text 0.30, accents L 0.50 with chroma 0.09-0.12, warning as ochre at hue 70 since no legible bright yellow exists on light. Variables and punctuation are foreground.
- Whiplash stays a literal palette because monochrome cannot be expressed as hues.
- Tests add APCA floors (text 75, syntax and status 60, comments 45) beside the WCAG checks.

Icon themes, one per era, generated from `src/icons/`:

- `pixelfont.ts` is a 3x5 bitmap font rendered as SVG paths. `svg.ts` draws a document chip and a folder, colored from the palette by role. `catalog.ts` maps about 100 file kinds and 25 folder kinds to a label and role. `build.ts` writes `icons/<slug>/*.svg` plus the icon theme JSON, and `contributes.iconThemes` is generated alongside `contributes.themes`. Output is gitignored and regenerated by the build.

Runtime (`src/extension/`), bundled by esbuild to `dist/extension.cjs`:

- Commands to choose, step and randomize eras, each setting `workbench.colorTheme` and `workbench.iconTheme` globally. A status bar item shows the active era. When the color theme changes to an era and `aespa.syncIconTheme` is on, the icon theme follows. On startup the sync only runs if an era icon theme is already active, so installing never hijacks another icon set.
